The NOVA platform

Three components. One modernization path.

Orbit adapts to how applications connect. Aster connects compatible backends. Vista provides the workspace. Nexus, the build and operations toolkit, joins in a later phase.

NOVA package — early releaseOrbit · Vista · Aster

O

Orbit

Application connectivity · business orchestration

In development

Multiple ingress gateways can be tailored to existing application calls and data, with shared business orchestration. The aim is to preserve integrations and limit changes to connected systems.

  • Customizable gateways for existing clients
  • Shared business flow orchestration
  • Authentication, load limits and timeouts
  • No automatic retry when the outcome is unclear

V

Vista

A workspace for users

Integrating with Orbit

Menus, tabs, forms and tables in one focused experience. The application shell is usable; sign-in and Orbit integration are being completed.

  • Menus, tabs and working tables
  • Forms, tables and actions
  • Consistent number, currency and date formats
  • Secure sign-in through a server-side gateway
View the NOVA model →
A

Aster

Connect the business backend

Simulation tested · verification ongoing

Connects Orbit to compatible backends, mapping data and managing processing sessions through connection profiles. Each backend and business scope needs integration verification.

  • Two-way data mapping
  • Session and processing management
  • Session cleanup on completion
  • Connection profiles for compatible backends

N

Nexus

Build and operations toolkit

Later phase · used on its own

Prepare builds, environments and test data for backend changes. The underlying tools have been used in live environments; the integrated NOVA experience belongs to a later phase.

  • Shorten backend build cycles
  • Simplify backup, restore and environment refresh
  • Move test data for support and debugging
  • Work directly in VS Code

E

Echelon

Multi-agent orchestration

Later phase · qualification ongoing

Additional orchestration for flows that need multiple agents or per-step control. Echelon is a peer component and participates when a flow needs it.

  • Split tasks across multiple agents
  • Balance load per step
  • Handle errors per step
  • Only when a flow needs it

How to get started

Assess one capability before expanding.

Agree on what needs to be demonstrated, how to measure it and the conditions for delivery. Assessment results provide a basis for choosing the next investment scope.

  1. 01

    Establish the baseline

    Choose the capability, backend and connected applications, then identify the priority problem.

  2. 02

    Define the assessment

    Agree on compatibility requirements, test data, measurement methods and acceptance criteria.

  3. 03

    Verify the results

    Compare business results, performance and operational effort with the current baseline for the same scope.

  4. 04

    Recommend the next step

    Identify what can proceed or needs further verification, with requirements and an indicative investment scope.
